# 광고 종료 캘린더 동기화

Google Sheets의 `MM월 DD일 종료` 시트를 읽어 **Google Calendar(ksh94love@gmail.com)** 에
광고 종료 일정을 자동 등록/갱신하는 Apps Script입니다.

Google Apps Script의 **시간 기반 트리거**로 Google 서버에서 실행되므로
Mac/PC가 꺼져 있거나 잠자기 상태여도 매일 동작합니다.
Apple 캘린더에서는 이 Google 계정을 동기화하면 그대로 보입니다.

---

## 1. 설치 (10분, 최초 1회만)

> ⚠️ 이 단계는 반드시 **ksh94love@gmail.com 계정**으로 진행하세요.
> 다른 계정으로 승인하면 그 계정의 캘린더에 접근하려다 실패합니다.

### 1-1. Apps Script 프로젝트 열기

1. [대상 스프레드시트](https://docs.google.com/spreadsheets/d/1Sfru4Lfl7cVEXjyZuaqq1qye5UNDghctsSiL6ISeuh8/edit) 를 엽니다.
2. 상단 메뉴 **확장 프로그램 → Apps Script** 를 클릭합니다.

### 1-2. 새 파일 추가 (기존 코드는 절대 건드리지 않음)

1. 왼쪽 **파일** 패널의 **＋ → 스크립트** 를 클릭합니다.
2. 파일 이름에 **`광고 종료 캘린더 동기화`** 를 입력합니다. (`.gs`는 자동으로 붙습니다)
3. 새로 만들어진 파일의 기본 내용(`function myFunction() {}`)을 **전부 지우고**,
   이 저장소의 [`광고 종료 캘린더 동기화.gs`](./광고%20종료%20캘린더%20동기화.gs) 내용을 **그대로 붙여넣습니다.**
4. **저장**(Ctrl/Cmd + S).

> 기존 `.gs` 파일들은 열지도, 수정하지도 마세요. 이 코드의 모든 전역 이름은
> `adEndSync` / `AD_END_SYNC` 접두사를 쓰기 때문에 기존 코드와 충돌하지 않습니다.

### 1-3. 열 매핑 확인 (권장, 1분)

함수 선택 드롭다운에서 **`adEndSyncCheckColumns`** 를 고르고 **실행**합니다.
처음 실행이면 권한 승인 창이 뜹니다 → 계정 선택 → **고급 → (프로젝트 이름)(으)로 이동 → 허용**.

실행 로그에 B/C/H 열이 각각 무엇으로 읽히는지 출력됩니다.

```
헤더 B/C/H: ["업체명","종료 광고 키워드","종료일"]
2행 → B(업체명)=알파상사 / C(키워드)=여름세일 / H(종료일)=2026-08-10
```

기대와 다르면 파일 상단 `AD_END_SYNC_CONFIG` 의 숫자만 바꾸면 됩니다
(A=1, B=2, C=3, … H=8).

### 1-4. 설치 실행

함수 드롭다운에서 **`adEndSyncInstall`** 을 고르고 **실행**합니다.

이 함수 하나가 다음을 전부 수행합니다.

| 단계 | 내용 |
|---|---|
| 1 | 스프레드시트 · 캘린더 접근 권한 확인 |
| 2 | 기존 동기화 트리거 **전부 삭제** (중복 트리거 방지) |
| 3 | 매일 **오전 8시 30분 전후**(Asia/Seoul) 트리거를 **1개만** 생성 |
| 4 | 트리거를 **다시 조회해서** 실제로 생성됐는지 검증 (1개가 아니면 오류) |
| 5 | 설치 직후 **1회 동기화 실행** (다음 날까지 기다릴 필요 없음) |

실행 로그에 아래와 같은 한국어 리포트가 출력되면 설치 완료입니다.

```
=== 광고 종료 캘린더 동기화 설치 완료 ===
스프레드시트 접근: OK (김승환 현황)
캘린더 접근: OK (ksh94love@gmail.com)
기존 트리거 정리: 0개 삭제
트리거 생성 검증: OK (트리거 ID ...)
자동 실행 시각: 매일 오전 8시 30분 전후 (Asia/Seoul, ±15분 변동)
생성된 트리거 수: 1개

── 설치 직후 1회 동기화 ──
실행 시각: 2026-08-03 14:22:10 (Asia/Seoul)
대상 종료일: 5일
신규 5건 / 갱신 0건 / 유지 0건 / 실패 0건
```

**이제 매일 자동으로 실행됩니다. 직접 실행할 필요가 없습니다.**

## 2. 설치 후 검증

| 실행할 함수 | 확인 내용 |
|---|---|
| `adEndSyncVerifyTriggers` | 트리거가 정확히 1개 등록됐는지 |
| `adEndSyncDryRun` | 캘린더를 **변경하지 않고** 신규/갱신/유지 건수만 미리보기 |
| `adEndSyncVerifyDuplicates` | **중복 키워드 날짜의 시트 행 수 == 캘린더 건수** 검증 |

`adEndSyncVerifyDuplicates` 출력 예시 — 중복 키워드가 있는 날짜만 골라서 대조합니다.

```
=== 중복 키워드 검증 ===
✅ 2026-08-10 | 시트 행 수 3 | 캘린더 제목 3건 | 캘린더 설명 항목 3개
     1. 여름세일 (알파상사)   ← 08월 10일 종료 2행
     2. 여름세일 (베타상사)   ← 08월 10일 종료 3행
     3. 가을신상             ← 08월 10일 종료 4행
검증 결과: 통과 1건 / 불일치 0건
```

트리거 실행 이력은 Apps Script 왼쪽 메뉴 **실행** 에서 매일 확인할 수 있습니다.

## 3. Apple 캘린더에서 보기

Apps Script 쪽에서 할 일은 없습니다. macOS/iOS에서 Google 계정만 연결하면 됩니다.

- **macOS**: 시스템 설정 → 인터넷 계정 → Google → `ksh94love@gmail.com` 로그인 → **캘린더** 체크
- **iOS**: 설정 → 캘린더 → 계정 → 계정 추가 → Google → 로그인 → **캘린더** 켜기

> 일정을 **비공개(private)** 로 만들지만, 계정 소유자 본인에게는 정상적으로 보입니다.
> **투명(transparent)** 설정이라 "일정 있음/바쁨" 상태에는 영향을 주지 않습니다.

## 4. 동작 규칙

### 시트 읽기
- `MM월 DD일 종료` 형식의 탭만 대상. 그 외 탭(요약/설정 등)은 건너뜁니다.
- 시트가 최신 → 과거 순으로 정렬돼 있다고 보고, **과거 날짜 탭을 만나면 그 뒤 탭은 읽지 않습니다.**
- 1행은 헤더로 건너뜁니다.
- **H열의 종료일**을 기준으로 **C열 키워드**를 수집합니다. H열이 비면 시트 이름의 날짜를 씁니다.
- 오늘(포함) 이후의 종료일만 처리합니다.
- **빈 키워드 행만 제외**하고, 나머지는 **시트의 행 순서를 그대로 유지**합니다.

### 중복 키워드 (중요)
- 같은 키워드가 여러 행에 있어도 **절대 중복 제거하지 않습니다.** 2행이면 캘린더에도 2건입니다.
- 중복된 키워드에만 **B열 업체명을 괄호로** 붙여 구분합니다: `여름세일 (알파상사)`
- 중복이 아닌 키워드에는 괄호를 붙이지 않습니다.

### 캘린더 일정
- 종료일 **오전 9:00 ~ 9:30** (30분)
- 제목: `[광고 종료] 광고 N건`
- 설명:
  ```
  Google Sheets: [김승환 현황]
  1. 첫 번째 키워드
  2. 두 번째 키워드
  3. 세 번째 키워드
  ```
- **비공개**, **투명**(일정 있음 상태에 영향 없음), 신규 일정에 **팝업 알림**(09:00 정각)

### 동기화 판정
| 상황 | 동작 |
|---|---|
| 그 날짜에 `[광고 종료]` 일정이 없음 | **신규** 생성 |
| 일정이 있고 제목·설명이 시트와 같음 | **유지** — API 호출 0회 |
| 일정이 있고 내용이 다름 | **갱신** — 제목·설명만 PATCH 1회 |
| 시트에서 날짜가 사라짐 | **아무것도 하지 않음** — 자동 삭제 없음 |

Google Calendar의 단시간 변경 제한을 피하기 위해:
- 기간 전체의 기존 일정을 **조회 1회**로 가져옵니다 (날짜별 조회 안 함).
- 신규 생성은 모든 속성을 **insert 1회**로 설정합니다.
- 갱신은 제목·설명만 **patch 1회**. 시간·알림·공개범위·투명도는 다시 쓰지 않습니다.
- 변경할 것이 없으면 **쓰기 호출을 아예 하지 않습니다.**

## 5. 설정 변경

파일 상단 `AD_END_SYNC_CONFIG` 의 값만 바꾸면 됩니다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `COL_COMPANY` / `COL_KEYWORD` / `COL_END_DATE` | `2` / `3` / `8` | B / C / H 열 |
| `EVENT_HOUR` / `EVENT_DURATION_MIN` | `9` / `30` | 일정 시작 시각 / 길이 |
| `REMINDER_MINUTES` | `0` | 팝업 알림. `10`이면 10분 전 |
| `TRIGGER_HOUR` / `TRIGGER_NEAR_MINUTE` | `8` / `30` | 자동 실행 시각 |
| `INCLUDE_TODAY` | `true` | `false`면 내일 이후만 처리 |
| `STOP_AT_FIRST_PAST_SHEET` | `true` | `false`면 모든 탭을 끝까지 읽음 |
| `SHEETS_LABEL` | `김승환 현황` | 설명 첫 줄에 표시될 이름 |

자동 실행만 멈추고 싶으면 **`adEndSyncUninstall`** 을 실행하세요.
트리거만 삭제되고 기존 캘린더 일정은 그대로 남습니다.

## 6. 문제 해결

**설치 시 "스프레드시트를 열 수 없습니다"**
기존 코드 어딘가에 `@OnlyCurrentDoc` 주석이 있으면 `openById`가 막힙니다.
이 스크립트는 자동으로 컨테이너 문서(`getActive`)로 대체하므로,
스프레드시트에 연결된 프로젝트라면 그대로 동작합니다.

**"캘린더에 접근할 수 없습니다"**
승인한 계정이 `ksh94love@gmail.com`이 아닙니다.
Apps Script 오른쪽 위 계정을 확인하고 다시 `adEndSyncInstall` 을 실행하세요.

**트리거는 있는데 일정이 안 생김**
Apps Script 왼쪽 **실행** 메뉴에서 실패 로그를 확인하세요.
`adEndSyncDryRun` 을 실행하면 시트에서 몇 건을 읽었는지 즉시 알 수 있습니다.
`대상 종료일: 0일`이면 시트 이름 형식이나 H열 날짜를 확인해야 합니다.

**날짜가 1년 어긋남**
시트 이름에 연도가 없어(`MM월 DD일 종료`) 오늘 기준 가장 가까운 연도로 추론합니다
(12월 → 1월 전환 대응). H열에 `2026-01-10` 처럼 연도를 넣으면 추론 없이 그 값을 씁니다.

## 9. 네이버 쇼핑 순위 조회 (`네이버 쇼핑 순위 조회.gs`)

`msearch.shopping.naver.com/search/all?query=키워드` 검색 결과에서 **광고 표시가 붙은
상품을 제외한** 순위를 스프레드시트에 기록하는 별도 Apps Script입니다.
전역 이름은 전부 `naverRank` / `NAVER_RANK_` 접두사를 쓰므로 위 캘린더 동기화 코드와
충돌하지 않습니다. 설치 방법은 1-2와 동일하게 **새 스크립트 파일 추가** 후 내용을 그대로
붙여넣으면 됩니다.

> ⚠️ **알려진 한계**: 네이버 쇼핑은 데이터센터 IP(Google Apps Script 서버 포함)에서의
> 접근을 비정상 트래픽으로 판단해 `HTTP 418`로 차단하는 경우가 있습니다. 이 스크립트는
> 이를 우회하지 않고, 차단되면 결과의 **비고** 칸에 그 사실을 그대로 적습니다. 실행 전에
> `naverRankDebugFetch()` 를 먼저 돌려 접속이 되는지 확인하세요. 또한 한 번의 요청으로
> 받아오는 검색 결과(첫 페이지 분량)까지만 순위 계산에 사용합니다 — 더 뒷 페이지까지
> 넘기지는 않습니다.

### 사용법

1. 스프레드시트에 **`네이버쇼핑 순위조회`** 라는 이름의 시트를 만들고 아래 순서로 열을 채웁니다.

   | A | B | C | D | E | F | G | H |
   |---|---|---|---|---|---|---|---|
   | 검색 키워드 | 상품명 매칭 문자열(필수) | 판매처 매칭 문자열(선택) | *(결과) 순위* | *(결과) 상품명* | *(결과) 판매처* | *(결과) 조회시각* | *(결과) 비고* |

   - B열은 검색 결과 상품명에 **부분 포함**되면 매칭되는 문자열입니다 (대소문자 무시).
   - C열은 같은 상품명을 여러 판매처가 팔 때 특정 판매처로 좁히고 싶을 때만 채웁니다.
   - D~H열은 실행 후 자동으로 채워집니다.

2. 함수 드롭다운에서 **`naverRankCheckAll`** 을 선택해 실행하면 모든 행을 순서대로 조회합니다.
   - 순위는 **광고를 제외한** 상품만 세어서 매깁니다.
   - 매칭되는 상품을 못 찾으면 순위는 비워두고 비고에 `미노출 (...)` 사유를 남깁니다.
   - 차단·오류가 나면 비고에 원인을 남기고 다음 행으로 넘어갑니다 (전체가 멈추지 않음).
   - 키워드마다 약 1.2초씩 대기해 짧은 시간에 몰린 요청으로 보이지 않게 합니다.

3. 시트 없이 키워드 하나만 바로 확인하고 싶다면 `naverRankCheckKeyword(키워드, 상품명매칭, 판매처매칭)` 을
   스크립트 편집기에서 직접 실행하고 실행 로그를 확인하면 됩니다.

### 문제 해결

**비고에 "접속 차단됨"이 계속 뜸**
`naverRankDebugFetch('아무 키워드')` 를 실행해 로그를 확인하세요. HTTP 418/403/429가 보이면
현재 Apps Script 서버 IP가 네이버 쪽에서 일시 차단된 상태입니다. 시간을 두고 다시
시도하거나, 조회 빈도를 줄여보세요 (이 스크립트가 대응할 수 있는 문제는 아닙니다).

**비고에 "페이지 구조가 바뀌었을 수 있음"이 뜸**
네이버가 검색 결과 페이지의 내부 데이터 구조를 바꾼 경우입니다. `naverRankDebugFetch` 로그로
실제 HTML/JSON을 확인해 `naverRankFindProductArray_` / `naverRankIsAdItem_` 의 필드명
후보 목록을 실제 구조에 맞게 수정해야 합니다.

**항상 미노출로 나옴**
B열(상품명 매칭 문자열)이 실제 검색 결과에 노출되는 표기와 다를 수 있습니다. 더 짧고
일반적인 부분 문자열로 줄여보세요.

## 10. 참고: 요구사항의 열 정의 충돌

원 요구사항에 B열이 두 가지로 적혀 있었습니다.

- 대상 정보: `B열: 작업 종료일`
- 규칙 4: `H열의 종료일을 기준으로`
- 규칙 6: `B열의 업체명을 ()에 넣어줘`

더 구체적인 규칙 4·6을 따라 **H = 종료일 기준, B = 업체명**으로 구현했습니다.
`adEndSyncCheckColumns` 로 실제 시트와 대조해 확인하고, 다르면 설정값만 바꾸면 됩니다.
만약 B열에 실제로 날짜가 들어 있어도 괄호 표기를 자동으로 생략하므로 깨지지 않습니다.
